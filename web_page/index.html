Element paths

Every comic is scraped by trying these in order: the first that matches a page is the one used. Paths that came with the script can be turned off but not deleted, so an update to the script cannot quietly put back one you did not want. Order matters when two match the same page.
How to add a path for a new comic
  1. Paste one of the comic's pages below (a page in the middle, not the newest) and press Check this page. If the comic image and next page lists already match, there is nothing to add.
  2. When nothing matches, the check suggests paths from the page's own images and links. Press add it beside one to put it at the top of its list.
  3. To write one yourself, right-click the comic in your own browser, choose Inspect, and look for an id or class that says what it is. Typing $x('//img[@id="strip"]') in the browser's console shows what a path matches.
  4. Press Save, then check the page again to see it used.
  • An image path has to end on the <img> itself: //*[@id="comic"]//img, not //*[@id="comic"].
  • Use ids and classes rather than positions like /html/body/div[3]/img, which break when the site is redesigned.
  • Keep next paths to links (//a[...]). A match in the page's head clicks nothing.
  • First page paths are only for walking a comic whose start was never recorded: the walk begins at the latest page it knows and follows one back to page 1, and stops if none matches. Check one of the comic's later pages to see which would be used.
  • Put a path written for one comic above the general ones, and note which comic it is for.
The paths that came with the script are examples of the most common layouts; their notes say which.

Check chapter list

reads the page, walks nothing
Fetches a comic's archive page and says what it would be read as: how many chapters, what each is called, and which page each starts at. It downloads nothing and changes nothing, so it is the cheap way to find out whether a page is usable before committing a comic to it. Give one of the comic's own page addresses so it can tell that comic's pages from everything else linked there.
Its first page will do. Only needed when the comic is not in the library yet.

Chapter boundaries

Where each chapter starts, as the archive page or the comic's own addresses were read. A site that names one page oddly - a cover called 20-an-odd-name where every other is issue-20-cover - puts a boundary in the wrong place, and no rule can tell. Change one here and it is written down as a correction: working the chapters out again, from a fresh reading of the archive or of the addresses, keeps it. Renaming a chapter to one that is already there moves that chapter to the new page instead of adding a second of the same name. A comic whose chapter archives are already written has the ones that changed written again on the spot, since an archive holding a boundary you just corrected is a wrong archive.
